# 竖屏知识短视频（studio 生产线）

一条片 = 一个生活里的现象 → 一层层讲到背后的道理 → 再回到生活。画面是程序渲染的 3D 小场景，没有真人出镜；声音是合成的原创配乐，旁白可有可无。

生产线在项目根目录下的 `studio/`（和 `CLAUDE.md` 同级）。先确认这个目录和 `studio/tools/render.mjs` 存在；不存在就告诉用户，不要凭空重建。所有命令都在 `studio/` 下运行。

**哪份说明算数：** `studio/README.md` 是引擎 API 的手册，可以照着查。但 README、`templates/` 和 `000-demo` 里关于风格的描述有一部分是旧标准（写实贴图、无旁白、Argon 起稿、"某理论认为"）。用户看过成片后改掉了这些，以本文件为准。样片是 `episodes/001-exam-dream`，不是 `000-demo`。

## 开工前先定四件事

从用户的话里能看出来的就不要再问；看不出来的，一次问完。

1. **主题和系列。** 哪个号、哪个系列，决定选题范围和引用规则：
   - 精神分析 /《梦的解析》（向心棱镜）→ 读 `references/series-psychoanalysis.md`
   - 教育学、学习科学、认知心理学、AI 时代的学习（老陈教你AI+教育）→ 读 `references/series-laochen.md`
   - 其他主题 → 只用本文件的通用标准，引用规则见"文案"一节。
2. **语言：** 中文、英文，还是双语。
3. **旁白：** 要还是不要。要的话需要豆包语音配置（见下）。
4. **时长：** 用户只说过"可以长一点"，要把道理讲透；没有给具体数字。第 1 集做成了约 2 分半，拿它当默认值，用户另有要求就听用户的。

### 语言开关（实际机制）

| 想要 | 怎么做 |
|---|---|
| 双语 | `subs.json` 每一屏都写 `text`（中文）和 `en`，`episode.json` 写 `title_en`。3D 画面只渲染一次，两个版本只换字幕层 |
| 只要中文 | 所有屏都不写 `en`。只要有一屏缺 `en`，就不会出英文版 |
| 只要英文 | 引擎以中文为底，`text` 仍然必填。有旁白时只跑 `voice.mjs <ep> --lang en`，并确保没有 `out/voice_zh.wav`，就只出英文版；没有旁白时两个版本都会渲染，把中文那个丢掉即可 |

双语时两种语言共用同一条时间轴，所以英文要短（每屏不超过约 14 个单词），要像英语母语者说的话，不要逐字直译。

### 旁白开关（实际机制）

**要旁白：**

1. 检查 `studio/.env` 里 `DOUBAO_API_KEY`、`DOUBAO_VOICE_ZH`、`DOUBAO_VOICE_EN` 是否已填（只检查有没有值，例如 `grep -cE '^DOUBAO_API_KEY=.+' .env`，输出 1 就是填了）。key 的值不要读出来、打印、贴进对话或写进任何别的文件。没填就请用户按 `.env.example` 自己填，key 来自火山引擎控制台的豆包语音。
2. 现用音色：中文 `zh_male_yuanboxiaoshu_uranus_bigtts`（渊博小叔），英文 `en_male_russell_uranus_bigtts`（Russell，英式）。换系列想换音色时，用 `voice.mjs --sample` 出几条试听让用户挑。
3. 文案定稿后运行 `node tools/voice.mjs <ep>`（单语言加 `--lang zh` 或 `--lang en`）。它会写出 `timeline.json`，此后每屏时长由配音长度决定。`sec` 仍然每屏都要写（估个大概）：合成之前引擎靠它排时间，缺了时长会算成 NaN。
4. 一句话跨几屏时，给前面的屏标 `"cont": true`，这几屏会合成一口气念完。详见 README"旁白"一节。
5. 改了文案就重跑 `voice.mjs`，只会重新合成改过的屏。

**不要旁白：**

- 不跑 `voice.mjs`，每屏时长 = `sec × scale`，观众靠读字幕，所以每屏给足 2.5 到 4.5 秒。
- 如果这一集以前做过旁白，要同时删掉 `episodes/<ep>/timeline.json` 和 `episodes/<ep>/out/voice_*.wav`。只删前者不够：`render.mjs video` 只要看到 voice wav 就会把旁白混进去，并且只出有旁白的语言。

## 流程和三个检查点

用户要在三个地方亲自看过才往下走。跳过检查点直接渲染，返工成本最高，这是前几轮踩出来的。

1. **建集：** `node tools/new-episode.mjs <三位编号-英文短名> "<中文标题>"`。它生成的 `copy/brief.md` 和 `scene.js` 是旧模板，命令行里提示的"run Argon"也不用理会；文案按下一步的说明起稿，场景照 `001-exam-dream` 的写法来。
2. **文案 → 检查点一。** 按 `references/copy-brief.md` 起稿，逐屏写出字幕（双语时中英一起），并在每屏旁边写一句这屏画面是什么。给用户看，同意后再写进 `subs.json`。
3. **旁白**（如果要）：`voice.mjs`，看它打印的每屏时长，过短或超过 7 秒的屏回头调整文案。
4. **素材：** 在 `episode.json` 的 `assets` 里列出模型，`node tools/fetch-assets.mjs <ep>`；不知道名字先 `--search <词>`。
5. **场景：** 写 `scene.js`。标准见下面"画面"，API 见 README 和 `references/engine-notes.md`。
6. **缩略图 → 检查点二。** `node tools/render.mjs contact <ep> 1.5`（英文加 `--lang en`），自己先逐张看一遍：构图、穿模、过曝、字幕压住主体、转场途中的空镜。然后把 `out/sheet_N.jpg` 发给用户，等用户说可以。
7. **配乐：** 写 `score.py`，时间只用 `s.T('S2', 0)` 这类引用，别写死秒数。标准见"配乐"。
8. **成片：** `node tools/render.mjs video <ep>`，输出 `out/<标题>.mp4`（和 `out/<title_en>.mp4`）。用 `ffprobe` 核对时长，响度应在 −16 LUFS 附近。
9. **试听 → 检查点三。** 你听不到声音。交付时直说这一点，请用户听旁白的读音、语气和配乐的感觉。
10. **发布**（用户要求时）：标题、正文、话题、封面先给用户看，得到明确同意才点发布。创作平台不能切换账号，先确认浏览器里登录的是哪个号；登录和退出由用户自己做。大文件上传的办法见 `references/engine-notes.md`。

工作量大时，文案、场景、配乐可以分给子代理并行做。用户定的是用 Opus（Agent 工具的 `model: opus`）来做视频和文案。子代理交回来的缩略图要你自己看过。

## 文案

想让观众得到的感受：有意思，说出了我有过但说不出来的感觉，想转给朋友。

- **剥洋葱的结构：** 表象（大家都有的生活场景）→ 一层一层往里讲（谁发现了什么、为什么会这样）→ 讲到最里面那一层 → 再一层一层回到生活，落在一句温和、让人松一口气的话上。每一层都要比上一层多回答一个"为什么"。
- **讲解段用连贯的完整句子，娓娓道来。** 不要每屏一个反转短句；用户说过那样"生硬"。
- **真诚、有点幽默，像懂行的朋友在说话。** 不用黑话和网络烂梗，不堆比喻，不写金句腔。
- **不出现元信息：** "本期""今天我们聊""关注我""点赞收藏"都不要。
- **不加防御性的学术声明。** 不写"这只是一种理论""并非诊断"之类的话，它们会冲掉情绪价值。准确性靠下一条来保证，不靠免责声明。
- **归到某个人、某本书名下的话，必须在原文里核对过。** 自己加的衔接句可以有，但不要安到作者头上。
- **有旁白时，字幕就是要念的词：** 每屏连起来要读得通，停顿处写出标点；`small` 小字不念。
- 每屏最多两行，中文每行不超过 13 个字。

## 画面

- **干净的纯色哑光材质，不用写实贴图。** 用户觉得写实贴图"显得质感很廉价"，整体也不要阴沉。配色柔和、明亮、有梦幻感；`001-exam-dream` 用的是粉、薰衣草紫、奶油色。新系列可以换一套配色，但先出两三张静帧让用户挑，别自己定了就全片铺开。
- **说到什么，就去到那个场景。** 旁白提到一间书房、一场考试、明天的会议室，镜头就真的飞到那个立体小场景里。不要在一个虚化的背景上叠 2D 小卡片撑完一整段；用户说过那样"特别空洞，缺少信息量和场景感"。差不多每一两屏字幕对应一个看得出在讲什么的画面。
- **没有 3D 人物。** 空房间加第一人称视角，靠物件说话。真实人物的历史照片可以作为画里的相框、书页出现。
- **一镜到底：** 机位在场景之间有空间感地移动，移动时虚焦、停下时聚焦。不硬切。
- **写实场景和抽象结构来回切换**，用户特别喜欢这一点：具体的房间讲现象，悬在虚空里的几何体、光线讲结构。
- 字幕区在画面下方，主体放在 y < 1300 像素的范围里。

## 配乐

程序合成的原创音乐（`music/synth.py`），没有版权问题。要温暖、有旋律、调性明确，跟画面里的事件对上点；避开不协和音、空洞的氛围声和悬疑感，用户说过那样"非常诡异"。有旁白时音乐会自动让位，不必自己压音量。

## 标题和发布文案（小红书）

- 标题用读者自己的体验发问，留悬念，不超过 20 个字。不出现理论家的名字，不把答案说破。例：「毕业多年，你是否还在做关于考试的梦？」
- 正文三小段：现象 → 书里或研究里怎么说 → 落回生活的那句话。话题 4 到 5 个。
- 封面：挑一个没有字幕的时刻渲染一张静帧（片头留白处，如 `node tools/render.mjs still <ep> 1.0 <底图.png>`），再用本 skill 的 `scripts/make_cover.py <底图.png> "第一行" "第二行" <ep>/out/cover_zh.jpg` 加两行大字（英文加 `--en`，`--band` / `--accent` 换色）。封面上的字可以比标题更直接。做完自己看一眼。

## 交付时要说清楚

哪些核对过（缩略图、时长、响度），哪些没法核对（声音），还留着哪些已知的小毛病。不要把没听过的东西说成没问题。
